# Decision log

Each entry records a decision, the alternatives considered, and why. New entries are added at the bottom. To reverse a decision, add a new entry that supersedes the old one.

Sources: **U** = decided by the user in the kickoff interview; **T** = a technical decision made by the lead architect.

| # | Decision | Source | Rationale / alternatives |
|---|---|---|---|
| D1 | The product's purpose is **steering and experimentation** with strong observability. It is not a security filter. | U | Shapes everything else: fidelity and reproducibility matter more than blocking threats. |
| D2 | Intercept with a **local Anthropic Messages gateway** (`ANTHROPIC_BASE_URL`) and rewrite outgoing `tool_result` blocks. | U | Controls exactly what the model sees, needs no certificate authority, and covers every tool. Rejected for v1: an HTTPS man-in-the-middle proxy, because WebFetch's extraction step filters changes made to raw pages, it doesn't cover WebSearch, and it needs a trusted certificate authority. Kept as a possible future optional mode. |
| D3 | The rewrite agent uses the **user's own Anthropic API key** behind a pluggable `RewriteProvider` interface. It never reuses Claude Code's intercepted credentials. | U | Fast, gives structured output, and is billed separately and transparently. Rejected: `claude -p` on the subscription (slow, little control over output) and local models in v1 (weaker results; they can come later through the interface). |
| D4 | v1 sessions are **app-launched only**, through the app or `diorama run -- claude`. Terminal CLI first, VS Code as a bonus, Desktop Code tab unsupported. | U | Opt-in by design, configuration is fixed before the first request, and nothing global is touched. Rejected for v1: global capture (if the daemon is down, every session breaks, and it disables Remote Control). Per the docs, the Desktop app ignores `ANTHROPIC_BASE_URL`. |
| D5 | v1 includes the **A/B experiment runner**, built only after interactive sessions are reliable. | U | Comparing against a control is central to the product: without one, rewrites can't be linked to behavior changes. |
| D6 | **Open-source quality** from day one, public on GitHub when ready. No Mac App Store. | U | It's a niche research tool, well suited to open source. The App Store sandbox conflicts with launching `claude` and with copying arbitrary project folders. |
| D7 | By default the rewrite agent gets **minimal context**: the rule instructions, the tool name and input, and the original result. Rules can opt in to task context. | U | Cheap, private and reproducible. Context-aware steering is available where a rule needs it. |
| D8 | The product name is **Diorama**. Tagline: "Stage what your coding agent sees. Measure what it does." | U | No collisions in developer tools or AI agents on Homebrew, GitHub or npm. Rejected: Counterfact (an existing API-mocking tool), Interpose (InterposeKit), Understudy (an existing AI-agent project), Morph (Morph LLM). A trademark search is still needed before launch. |
| D9 | **Freeze one decision per `tool_use_id`**, including "unchanged" and "failed", save it to disk before forwarding, and replay the exact bytes. | T | In the proof of concept, unstable replay silently corrupted what the model saw, with no error. Stable replay kept the prompt cache warm. Preserved-thinking enforcement makes edited history risky. |
| D10 | Edit the request by **splicing bytes** (replace only the content's byte ranges) instead of a parse-and-reserialize round trip. | T | Keeps every other byte identical, so prompt-cache prefixes, thinking-block consistency and unknown fields are all safe. Foundation's JSON round trip can reorder keys and change escaping. |
| D11 | Experiment treatments are **frozen across trials by default**, with a switch for fresh rewrites. | T | Trials measure Claude's response to one treatment, without adding the rewrite agent's own run-to-run variation. |
| D12 | The stack is **all Swift**: a SwiftUI app, plus a SwiftNIO gateway in a separate `dioramad` daemon, plus a CLI. All three come from one Swift package. | T | A native Mac app with no Node runtime to ship, and good contributor appeal. The daemon keeps sessions alive if the GUI crashes and lets the CLI work without the GUI. Rejected: a Node/TypeScript sidecar (faster to prototype, but heavier to distribute and two languages to maintain). |
| D13 | Storage is **SQLite through GRDB** plus a compressed, content-addressed blob store. | T | Reliable, queryable and observable. Large bodies stay out of the database, and identical content is stored once. |
| D14 | Sessions are identified by a **per-session token in the base URL path** (`/s/<token>`). | T | Verified in the proof of concept: Claude Code keeps the base path. It's set before the first request, needs no custom headers, and also stops other local processes from using the gateway. |
| D15 | An unknown or invalid session token gets **403 + `x-should-retry: false`**. | T | The proof of concept saw Claude Code retry a plain 401 nine times. |
| D16 | The rewrite call uses **structured output** (`output_config.format`), sends no sampling parameters, and uses `fallbacks: "default"` on Opus 5.5 and Sonnet 5.5. | T | Forced `tool_choice` returns a 400 on current models, and the API now rejects `temperature`, so determinism comes from caching. Refusals are recorded. |
| D17 | Minimum **macOS 15**, Swift 6 language mode, Swift Testing. App project generated with **XcodeGen**. | T | Modern SwiftUI and Observation. A generated project file avoids merge conflicts for contributors. |
| D18 | License: **Apache-2.0**. | T | A permissive license with an explicit patent grant, common for developer tools. Can be revisited before the first public commit. |
| D19 | The default rewrite model is **`claude-haiku-5-5`**, with Opus 5.5 and Sonnet 5.5 selectable per rule. | T (adopted with the plan) | Speed matters because each rewrite holds the request, and the price is $0.10/$0.50 per million tokens versus Opus 5.5 at $4/$20. Quality-sensitive rules can choose Opus. |
| D20 | **No XcodeGen.** The app is a SwiftPM executable target, and `scripts/bundle-app.sh` assembles and signs `Diorama.app`. The daemon and CLI go in `Contents/Helpers/`. | T (supersedes the XcodeGen part of D17) | XcodeGen wasn't available. A pure SwiftPM build is simpler for contributors and CI. The Helpers location also avoids `MacOS/diorama` overwriting `MacOS/Diorama` on case-insensitive volumes, a bug the first bundle actually hit. |
| D21 | The **control API runs on the gateway's loopback port** (`/api/v1`) with a bearer token from `daemon.json` (mode 0600), not on a Unix socket. | T (supersedes that part of the architecture) | URLSession can't speak HTTP over Unix sockets. Token plus file permissions plus `Host`/`Origin` checks give the same per-user protection. |
| D22 | **No live Anthropic API calls during development and testing.** Verification uses mock upstreams, a scripted model, fake rewrite endpoints, and the real `claude` CLI with a dummy key and a temporary HOME. | User constraint | Real calls cost money and need explicit authorization. The live smoke test is a documented release step (`docs/release.md`). |
| D23 | **System SQLite and URLSession** instead of GRDB and async-http-client. | T | Fewer dependencies. URLSession streams through a delegate without buffering, and handles HTTP/2, TLS and proxies. The wrapper is small and fully tested. |
| D24 | The rewrite agent returns **exact-match edits** (`find`/`replace`), or a full replacement only when needed. Diorama applies edits deterministically and splices only text segments. | T | Edits are cheaper and faster than regenerating whole pages, produce an auditable change list, and keep non-text blocks byte-identical. Invalid edits are retried once with the error included. |
| D25 | **`diorama run` supervises** Claude Code as a child process instead of using `execve`, and restarts the daemon on the same port if it dies. | T | Keeps routed sessions alive when the daemon crashes. Verified by killing the daemon mid-session. |
| D26 | **Lockdown uses `--settings` `permissions.deny`**, not `--disallowedTools`. | T | Settings JSON avoids parsing ambiguities with variadic CLI flags. A contract test verifies that Claude Code refuses the call. |
| D27 | Experiment trials use **blocked randomization**: every variant once per round, in seeded order. | T (refines D11) | A plain seeded shuffle produced "all steered, then all control" in a real run, which would let drift over time line up with one variant. |
| D28 | The **"echoed rewritten content" heuristic diffs original against replacement** instead of reading edit records. | T | Frozen treatments reuse a rewrite without creating attempts in later trials. Diffing works for edits, replacements and reuse alike. |
| D29 | **Pre-extraction mode** (rule `stage: page`): the raw page is rewritten in WebFetch's summarizing request. The request is tied to its WebFetch call through the preceding response (matched by prompt), the decision is keyed by `page:<tool_use_id>`, and the treatment key is URL plus page content (not the prompt). | T (supersedes the "pre-extraction later" item in requirements §5) | In the live pilot, frozen treatments couldn't be reused for WebFetch, because the summarizer's output varies. Raw pages are stable. No certificate authority is needed. The summarizing request isn't part of any conversation history, so replay only matters for retries of the same request, which are handled. |
| D30 | An **LLM judge** is opt-in per experiment and runs after the run on every successful trial, with controls as a baseline, against the changes derived from the rewrites. Its verdicts are stored with the heuristic signals. | User request (heuristic signals) | Pattern-match heuristics miss paraphrases. Running after all trials gives one shared list of changes, so controls and treatments are judged against the same thing. It's labeled as an interpretation and never mixed into the facts. |
| D31 | **Local models through Ollama**, routed by the `ollama:` model prefix, for rewrites and the judge. | User request | Offline experiments with no API cost. Provider selection per model keeps the provider interface (D3). It is tested against a fake Ollama server; it hasn't been tried with a real Ollama install. |
| D32 | A **plain update checker** instead of Sparkle: it reads GitHub Releases (public API, falling back to the `gh` CLI for private repositories) and notifies, and `diorama update --download` downloads and verifies the zip. Diorama never replaces itself. | T | The user doesn't want an Apple Developer account. Sparkle's safe updates depend on stable code signatures, which ad-hoc builds don't have. A verified download with manual install is honest and safe. |
| D33 | **UI testing through self-rendered snapshots** (`scripts/ui-smoke-test.sh` in CI), plus unit tests of the form logic, which was moved into `FormLogic`. No XCUITest. | T | XCUITest needs an Xcode project, and accessibility automation needs permissions the runner shouldn't have. The snapshot test renders every screen and sheet off-screen in the real app against a fresh daemon. |
| D34 | **Keep the name "Diorama" for now.** The user checks the trademark (a pending DIORAMA Class 042 application) before making the repository public. | U | Renaming touches the binaries, bundle ID, data folder and docs. It's deferred until the trademark question is answered. |
| D35 | **Menu bar presence.** Diorama has a menu bar icon. Closing the window keeps it running there, as an accessory app with no Dock icon, and the icon can be turned off. The daemon takes its single-instance lock before it opens the database. | U (menu bar, close behavior); T (lock order) | The user asked for a menu bar icon and for the close button not to quit the app. Adding a second connection path showed that two simultaneous daemon starts could race the database migrations: with the old order, a second daemon opened SQLite before failing the lock. |
| D36 | **Hook mode for the Claude desktop app and IDEs.** A `PostToolUse` hook (`diorama hook run`) sends each tool result to the daemon, which decides it with the same engine and returns `updatedToolOutput`. It is installed per project in `.claude/settings.local.json`; sessions are recorded with `via: hook`. | U (support Desktop); T (mechanism) | Supersedes the Desktop part of D4. Desktop sets `ANTHROPIC_BASE_URL` for every session, and settings files can't override it; this was verified with its bundled Claude Code. Desktop's own gateway mode is app-wide and requires signing out of claude.ai. Hooks are opt-in per project. Verified in the real Desktop app before building. Trade-offs: no model traffic, no pre-extraction, per-tool output mapping. The gateway stays primary and runs all experiments. |
| D37 | **AI control through an MCP server** (`diorama mcp serve`): a minimal JSON-RPC-over-stdio implementation in `DioramaClient` with no SDK dependency, built on the control API. Spending needs the estimate's confirmation token; the key, settings, deletion and shutdown are not exposed; `--read-only` exposes inspection only. | U (control Diorama with AI); T (mechanism, safety) | Keeps the dependency list at swift-nio and swift-argument-parser (D23). The protocol surface used is small (initialize, ping, tools/list, tools/call). Tool annotations mark read-only, destructive and spending tools so clients can ask appropriately. Verified with the real Claude Code calling a tool. |
| D38 | **Budget guard: daily caps that pass results through.** An overall cap (settings) and a per-profile cap (profile defaults) per local calendar day, checked before each rewrite call. Over a cap, results are forwarded unchanged and the session is flagged; paid previews are refused. Spending is counted from rewrite attempts in non-trial sessions plus a ledger for playground and what-if calls. Experiment trials are neither counted nor blocked. The MCP server can't change budgets. | U (caps with pass-through and a warning); T (scope) | Pass-through keeps Claude Code working, consistent with the failure policy (D9). Blocking a trial mid-run would corrupt an experiment whose cost the user already approved. Checking before the call can overshoot by one call; a reservation scheme isn't worth the complexity at these prices. |
